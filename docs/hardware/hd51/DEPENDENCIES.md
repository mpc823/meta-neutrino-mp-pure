# HD51 dependencies

## Open and build-time dependencies

- OpenEmbedded/BitBake Wrynose pins from `kas/hd51-wrynose.yml`.
- OE-Alliance `meta-oe` and `meta-brands/meta-gfutures` at the locked commit.
- Neutrino-MP layer and existing common dependencies from this repository.
- ARM `cortexa15hf-neon-vfpv4` toolchain generated by BitBake.
- `linux-gfutures_4.10.12.bb`, its defconfig, initramfs and kernel patches.
- `hdemmc_image_multiboot.bbclass` and native image tools (`parted`, mtools,
  e2fsprogs, zip) supplied through BitBake dependencies.

## External restricted dependencies

The current OE-Alliance recipes fetch, but do not build, vendor archives:

- `hd51-drivers-4.10.12-20250429.zip`: kernel modules; recipe license is
  closed/proprietary.
- `hd51-v3ddriver-20250217.zip`: Nexus/V3D/EGL/GLES libraries; recipe license
  is closed/proprietary.

The recipes contain SHA-256 values in `sources.lock.yaml`.  The archives are
not committed, mirrored, or redistributed by this project. A build may only
use them where their source and license terms permit it.

## Runtime hardware dependencies

The target requires the vendor kernel modules, `/proc/stb` interfaces, DVB
frontend/demux devices, framebuffer/OSD access and Nexus/V3D userspace. A
successful BitBake build does not prove hardware boot or video/audio output.
